# Step-by-step: register a REAL test-only Shopify Web Pixel extension

This repository currently contains a non-deployed prototype in
`web/prototypes/shopify-web-pixel/`. It is NOT a Shopify-registered extension.

## Safety boundary
- Use a separate Shopify **development app** linked to the HashTopic test store.
- Never run `shopify app deploy` against the current production
  `shopify.app.mystorefront-postback.toml` configuration.
- Never paste API secrets, private keys, auth codes, or pixel customer events
  into GitHub or a support conversation.
- Never turn on an observation endpoint until security, privacy, consent,
  replay prevention and retention have been reviewed.
- The eventual pixel must NOT issue commissions without verifying paid
  Shopify orders and deduplicating against existing theme-embed attribution.

## One-time CLI action requiring the app owner's Shopify login

1. Open a local clone of this repository with branch
   `experiment/shopify-web-pixel-attribution-20261104`.
2. Confirm there is a **separate development Shopify app/configuration**. If
   CLI offers to associate with the production MyStorefront Postback app,
   cancel. Do not deploy to the production client ID.
3. In the repository root, use Shopify CLI and select the development app:
   `shopify app generate extension --template web_pixel --name mystorefront-web-pixel`
   Choose **JavaScript**. The CLI generates an actual Shopify-owned UID in
   `extensions/mystorefront-web-pixel/shopify.extension.toml`.
4. Copy/adapt the research subscriptions from
   `web/prototypes/shopify-web-pixel/index.js` into the generated
   `extensions/mystorefront-web-pixel/src/index.js`. Initially keep events
   local-only, with NO network sending.
5. In the **development app configuration only**, request
   `write_pixels,read_customer_events` in addition to any existing scopes.
6. Set the generated extension's privacy configuration truthfully for
   affiliate measurement, respecting Shopify consent and data-sale rules.
   Do NOT label tracking "strictly necessary" to bypass consent.
7. Run `shopify app dev` for the **development app** and connect the
   HashTopic development store. This does not itself connect the pixel.
8. Only when the dev app has the required granted scopes, activate the
   dev pixel via Shopify's `webPixelCreate` GraphQL mutation, using the
   actual settings schema generated by Shopify CLI. Do not invoke that
   mutation on production stores.
9. Inspect **Shopify Admin > Settings > Customer events > App pixels**.
   Confirm the test pixel shows **Connected**.
10. On the test store, inspect whether allowed `page_viewed` and
    `checkout_completed` events arrive, including consent-off cases.
    No checkout is required for the first page-view test.

## Blockers to resolve before commissioning any further work
- A real Shopify-generated extension UID and dev app association are missing.
- There is no approved staging event-ingestion service or verified-order
  reconciliation yet; no attribution postbacks can be generated.
- A sandboxed pixel cannot replace the theme embed's cart property writes.
- Client ID continuity, checkout order-ID availability and privacy consent
  must be validated against actual Shopify event payloads in the test store.

Official reference: https://shopify.dev/docs/apps/build/marketing/build-web-pixels
